# 混合召回 RAG 知识库系统

> 向量语义召回 + BM25 关键词召回双路融合的检索系统，全链路离线。
> 每条召回结果强制携带 `citation`（条目 ID + 偏移量）与召回路径标记，
> **从机制上抑制编造，而不是靠 prompt 约束**。

| | |
|---|---|
| 后端 | FastAPI，**23 个模块 / 2,156 行 Python** |
| 向量模型 | `BAAI/bge-small-zh-v1.5`（本地部署，512 维） |
| 语音 | `faster-whisper`（本地部署，ASR） |
| 检索 | 向量语义 + BM25 双路，RRF / 加权归一化两种融合 |
| 中文分词 | CJK 单字 + 相邻双字 n-gram，**不引 jieba，零依赖** |
| 测试 | **82 例 pytest** |

## 一、为什么必须做混合召回

这个项目最初只有向量语义检索。实测中发现一个很具体的问题：

> **纯语义检索在专有名词和编号上会漏召回。**

比如查「工号 10086 的考勤记录」，向量模型会把「10086」当成普通数字，
语义上跟一串别的数字很接近，真正含这个工号的文档反而排不进候选池。

原因不难理解：embedding 是为**语义相似**优化的，而工号、订单号、人名这类 token
需要的恰恰是**精确匹配**，语义相似度在这里是噪声。

所以加了 BM25 一路。实测观察：**加了 BM25 之后正确结果的名次明显前移**。

---

## 二、三种融合策略

| 策略 | 实现 | 适用 |
|---|---|---|
| **RRF（倒数排名融合）** | `score = Σ 1/(k + rank_i)`，`k = 60` | 默认。**只用名次，免疫分数不可比问题** |
| **加权归一化融合** | min-max 归一化后按 `alpha` 加权 | 两路分数同量纲时，能利用分数强度信息 |

### 为什么默认用 RRF

不同检索器的分数**不可比**：cosine 相似度挤在 0.7~0.95 的窄区间，BM25 分数可能是 0~30 且无上界。
直接加权融合，权重没有物理意义，还得先做归一化。

RRF 只用名次，天然绕开量纲问题。代价是丢掉了分数里携带的置信度信息，
所以加权融合也一并保留，按需切换。

## 三、中文分词：为什么不引 jieba

```python
def tokenize(text):
    # 单字：过滤虚词（的了是在和与就都而…）
    # 双字：相邻 n-gram，且至少一个字为实义
```

三点考虑：

1. **零依赖**。jieba 要带词典，在离线部署场景里多一份负担。
2. **对未登录词天然友好**。工号、产品型号、人名这类词，词典里没有就是没有；
   n-gram 不看词典，切出来照样能命中。
3. **双字过滤虚词**是关键一步。只过滤单字虚词时，「的了吗呢」仍会切出
   `['的了','了吗','吗呢']` 这种噪声词，导致任何含「的」的中文文档都被误召回。
   所以双字要求**至少一个字为实义**，「目的」留下，「的了」丢掉。

### BM25 参数

`k1 = 1.5`（词频饱和，出现 10 次不该是 1 次的 10 倍价值）
`b = 0.75`（长度归一化，长文档天然词频高，要惩罚）
`idf = ln(1 + (N - df + 0.5) / (df + 0.5))`

## 四、Citation：把防编造做成机制，不是提示词

很多 RAG 系统的做法是「在 prompt 里写一句：请只根据给定内容回答」。
**prompt 约束在模型幻觉面前是靠不住的。**

这个项目的做法是在数据结构层强制：

```python
{
    "citation": {"entry_id": "...", "offset": 1234},   # 条目 + 偏移量
    "recall_path": "hybrid:vector+bm25",               # 召回路径标记
    ...
}
```

每条召回结果**必须**带 `citation` 和 `recall_path`，生成时只能引用带 citation 的片段。
这样「这句话是从哪来的」永远可查，不需要信任模型的自觉性。

切片策略：`300 字 / 50 字重叠`。

## 七、已知局限（诚实写在这里）

1. **当前语料规模很小（31 条条目）**。混合召回的价值在大规模语料上才更明显；
   小语料下 BM25 的收益主要来自专有名词那一类 case。
2. **没有做 rerank**。融合后的结果直接进生成，没有 cross-encoder 二次精排。
   如果语料规模上去，rerank 是下一步最该加的。
3. **没有接入向量数据库**。当前是内存索引（NumPy），
   万级以下够用；更大规模需要 FAISS / HNSW。
4. **融合权重 `alpha` 是人工设定的**，没有用标注数据做过网格搜索。
5. **检索效果目前只有定性观察**（"正确结果名次明显前移"），
   **缺少 MRR / Hit@K / Recall@K 的量化对比**。这是接下来要补的。
